Overview
This document defines the interoperability testing strategy for LSIS-AFS reference implementations. In-
teroperability ensures that different implementations can exchange signals and data correctly, validating
| compliance       | with the LSIS-AFS | specification. |     |     |
| ---------------- | ----------------- | -------------- | --- | --- |
| Interoperability | Goals             |                |     |     |

1. Signal Compatibility: Signals generated by one implementation can be decoded by another
2. Data Fidelity: Navigation data survives the encode-decode cycle across implementations
3. Specification Compliance: All implementations produce identical outputs for identical inputs
4. Cross-Platform Validation: Implementations in different languages produce compatible results

### Subframe 3 MVP parsing profile

Gateway 6 receives the complete 846-bit SB3 data field after Gateway 5 has
validated and removed the 24-bit CRC. The leading type field is read MSB-first
using `gateway3::kSb34TypeFieldBits`. The current reference profile selects four
type bits (bits 0-3) followed by 842 raw payload bits (bits 4-845). If
LSIS-TBC-2023 resolves the field to six bits, the shared configuration moves the
payload start to bit 6 and leaves 840 payload bits without changing the parser
API.

The LSIS does not yet assign numeric SB3 types, and MSG-G5 remains
LSIS-TBW-2007. For MVP routing only, this implementation assigns type `1` to a
provisional MSG-G5 Orbit Almanac header:

| Raw payload bits | Width | Decoded JSON field | Accepted values |
| ---------------- | ----- | ------------------ | --------------- |
| 0-7              | 8     | `prn`              | 0 (unspecified), 1-210 |
| 8-20             | 13    | `reference_week`   | 0-8191 |
| 21-29            | 9     | `reference_itow`   | 0-503 |
| 30-31            | 2     | `health`           | 0-3 |
| 32-end           | 810/808 | Not decoded      | Retained in `raw_payload` |

For example, the parsed-data shape for this provisional profile is:

```json
{
 "subframe3": {
  "type": 1,
  "data": {
   "prn": 42,
   "reference_week": 1234,
   "reference_itow": 256,
   "health": 1
  }
 }
}
```

All other type values are accepted as opaque messages: Gateway 6 returns the
numeric type and the complete `raw_payload` without a decoded value. This
includes MSG-S19/S20, MSG-G24, MSG-G32, MSG-G3, MSG-G23, MSG-G10, MSG-G11,
MSG-G14, MSG-G31, and custom LNSP messages until a specification or SISICD
assigns their type values and payload layouts. This provisional profile is a
software reference example and is not an operational MSG-G5 wire definition.
CRC failures and protected-bit corruption are rejected by Gateway 5 before this
parser is called.
